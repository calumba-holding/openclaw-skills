# GitLab MR 审查清单

GitLab 合并请求端到端系统化审查清单。

---

## 审查前检查

### MR 基本规范
- [ ] MR 标题清晰，符合 Conventional Commit 格式（feat/fix/docs/refactor…）
- [ ] MR 描述说明了**为什么**做这个改动，而非只说做了什么
- [ ] 关联了对应 Issue 或需求链接
- [ ] MR 变更范围合理（建议 ≤ 400 行改动，否则拆分）
- [ ] 目标分支正确（feature → dev，hotfix → main）
- [ ] 分支已同步最新目标分支（无合并冲突）

### CI/CD 状态
- [ ] Pipeline 全部通过（lint、test、build）
- [ ] 代码覆盖率未下降
- [ ] 无安全扫描报警（SAST/Dependency Scanning）

---

## 代码正确性

### 逻辑
- [ ] 算法正确实现需求，边界值已处理（null、空集合、极大值）
- [ ] 无 off-by-one 错误
- [ ] 循环终止条件正确
- [ ] 递归有正确的终止基础

### 错误处理
- [ ] 异常在合适层级捕获（不吞异常）
- [ ] 错误信息对调用方有意义
- [ ] 错误路径下资源被正确释放

### 并发安全
- [ ] 共享状态有适当锁保护
- [ ] 无竞态条件
- [ ] 数据库事务边界正确

---

## 安全

- [ ] 用户输入已验证/清洗（长度、类型、范围）
- [ ] SQL 使用参数化查询，无字符串拼接
- [ ] 无硬编码密钥、密码、Token
- [ ] 日志中不包含 PII 或敏感数据
- [ ] 认证/授权检查在操作执行前完成
- [ ] 文件上传限制了类型和大小

---

## 性能

- [ ] 无 N+1 查询问题
- [ ] 数据库查询有必要的索引支持
- [ ] 大集合处理使用分页或流式处理
- [ ] 无内存泄漏风险（资源、连接、监听器）
- [ ] 长耗时操作异步处理

---

## 可维护性

- [ ] 函数单一职责，长度 ≤ 50 行（建议）
- [ ] 嵌套层级 ≤ 4 层
- [ ] 命名清晰自注释，无无意义缩写
- [ ] 无重复代码（DRY）
- [ ] 无魔法数字（用常量替代）
- [ ] 无遗留的 TODO/FIXME（或有明确 Issue 链接）

---

## 测试

- [ ] 新功能有对应单元测试
- [ ] 关键路径有集成测试
- [ ] 测试覆盖边界条件和异常路径
- [ ] 测试命名清晰描述被测行为
- [ ] Mock 符合实际行为

---

## 文档

- [ ] 公共 API/接口有文档注释
- [ ] 复杂算法或非显而易见的决策有注释说明
- [ ] README / CHANGELOG 按需更新
- [ ] 破坏性变更提供迁移指南

---

## GitLab 特定检查

- [ ] Reviewer 已正确指定
- [ ] Label 已打（feature / bugfix / breaking-change 等）
- [ ] Milestone 已关联（如使用）
- [ ] WIP/Draft 标记已移除（准备合并时）
- [ ] Squash commits 设置符合团队规范

---

## 审核结论参考

| 情况 | 建议动作 |
|------|---------|
| 无问题或仅有建议性意见 | `glab mr approve <ID>` |
| 存在需要修改但非阻断问题 | `glab mr note` 说明，等待修复 |
| 存在 Critical/High 安全或逻辑问题 | `glab mr note` 标注 🚫 请求修改 |
| 架构级问题需要讨论 | 创建讨论线程，@相关成员 |
